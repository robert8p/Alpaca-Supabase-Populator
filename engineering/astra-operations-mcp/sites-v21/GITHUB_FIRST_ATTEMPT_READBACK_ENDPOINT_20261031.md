## Material additional **official** GitHub provider readback endpoint
GitHub's official [REST API — Get a workflow run attempt](https://docs.github.com/en/rest/actions/workflow-runs#get-a-workflow-run-attempt), accessed 2026-10-31, specifies a dedicated, read-only endpoint:
`GET /repos/{owner}/{repo}/actions/runs/{run_id}/attempts/{attempt_number}`
with `X-GitHub-Api-Version: 2026-03-10`; HTTP **200** on success, and repository **Actions:read** for fine-grained GitHub App installation/user or fine-grained PAT tokens on private repositories. The example response includes `id`, `run_attempt`, `head_sha`, `head_branch`, `workflow_id`, `path`, `event`, `status`, `conclusion`.

**New engineering implication:** when the generic run-id GET subsequently reflects a manual rerun, the exact first attempt can be queried as `/actions/runs/{owner-captured-original-run-id}/attempts/1`; an unrelated success, a later `run_attempt:2`, or latest generic run-id status must not be substituted for original attempt success. This is a possible **future controller-owned readback route**, not a change to current v21 acceptance semantics or proof that any actual first attempt has completed.
