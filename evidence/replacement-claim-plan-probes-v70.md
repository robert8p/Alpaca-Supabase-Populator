# Normal claim plan probes

These probes plan the exact normal candidate from the saved live dispatcher lines 123–134. They do not execute a claim, take task row locks, change a fence or contact a provider. Every statement runs in a read-only transaction with an eight-second statement deadline and three-second lock deadline. `FOR UPDATE OF q` remains in the plain `EXPLAIN` so the resulting plan retains its `LockRows` node. No `ANALYZE` is present.

Start with `replacement-claim-normal-generic-plan-probe-v70.sql`. It exposes a forced generic parameter plan. The custom JSON package contains one standalone statement for each of the sixteen families; use only additional individual plans needed to compare a suspected family. Each query uses the same exact run, twelve supported kinds and timestamp saved at 11:00:49.547058 UTC. The persisted rotation was CTX06, REF01, REF03, P01, P02, D01, D02, D03, D04, D05, N01, N02, N03, S01, S02, CTX02. That rotation does not identify which family timed out at 10:53:28.

Each probe checks that the expected normal candidate occurs exactly once in the current dispatcher source, preserves every cohort/fence/dependency/reuse/breadth/provider/lease/budget predicate, retains the full `q.*` projection and original ordering, and cleans up its named session-local prepared statement on success. A failed or interrupted probe may leave its prepared statement on that same database connection; reconcile or close that diagnostic session before replay rather than changing task state. The plan-mode setting is transaction-local and rolls back.

The output is one estimated JSON plan, including planner settings. Inspect task index and condition, estimated rows/cost, sorting, member-count InitPlan, dependency/gap subplans and planned breadth calls. Plans reflect indexes and statistics installed at probe time, including the newly built summary index if present. Estimates do not establish elapsed time, actual loops, the worker's cached auto-plan choice, which family reached the timeout, or successful recovery. No outer authenticated dispatcher or global advisory lock is measured. The input timestamp is the saved observation, not a claim-start timestamp recovered from the failed transaction.

The known worker timeout predates the summary index build. Parent should compare post-build worker progress and safe errors before deciding whether a claim repair is necessary. These probes contain no claim rewrite.
